# SportRX

> **把不同人群的运动处方逻辑做成可配置、可追溯、可测试的 Program Pack。**

SportRX 是一个人群化运动处方平台原型。通用内核负责安全路由、FITT-VP 接口、训练
记录、RPE、实际—计划差异、解释与导出；每个 `Program Pack` 决定某一类当前场景适用
哪些输入、规则、测量和自动化边界。动作内容库提供可筛选的动作、器械与操作说明，
但不决定训练剂量。

**开得稳，讲得清，能调整。**

## SportRX 解决什么问题

平台服务不同场景，但只对已发布、已审阅的 Pack 开放自动化。当前首个已发布闭环是：
一个表观健康、目前运动不足的成年人，在有限时间条件下，今天应怎样开始有氧运动，
并在之后逐周调整？

```text
当前场景 → Program Pack 路由 → 基础筛查 → 当前运动状态 → 可用时间
→ 当前周 FITT-VP 处方 → 每次训练完成情况 / RPE → 下一周调整
→ 可选查看 4 周适应性路线
```

## 核心体验

| 价值 | SportRX 的做法 |
| --- | --- |
| 开得稳 | 从近期活动量和可用时间开始，而不是把统一目标直接压给每个人。 |
| 讲得清 | 当前周展示 FITT-VP、RPE、说话测试和计划生成原因；未来周明确标为等待反馈。 |
| 能调整 | 每次训练记录完成情况与 RPE；周末汇总后决定维持、小幅进阶、降低训练量或暂停自动调整。 |
| 不越界 | 警示症状、相关疾病或不确定情况会阻断自动处方，不作医疗判断。 |

## Program Pack 状态

| 当前路径 | 发布状态 | 自动化边界 |
| --- | --- | --- |
| 久坐 / 低活动成人：有氧起步 | 已发布 | 当前周有氧 FITT-VP + 完成情况 / RPE 周调整。 |
| 一般体能建立：有氧基础 | 有限发布 | 自动化仅为有氧；力量只做动作内容和记录。 |
| 代谢健康关注、运动表现入门 | 仅评估 | 可识别场景和准备测量，不自动生成训练剂量。 |
| 高龄、孕产、青少年、慢病、康复 | 专业协作 | 在独立 Pack、专业审核和验证完成前不自动化。 |

完整逻辑见 [Program Pack 与平台路径](docs/zh-CN/program-packs.md)。

## 3 分钟体验

```bash
python3 -m pip install -e ".[dev,app]"
python3 scripts/smoke_check.py
bash scripts/run_local.sh
```

打开终端显示的本地地址后，按下面四步体验：

1. 在 **今天** 直接查看当前训练；没有处方时，从这里开始创建。
2. 在 **评估** 用两步填写目标、近期运动、可用时间和偏好方式。
3. 在 **进展** 每次填写是否完成、本次 RPE 与异常情况；系统自动汇总本周。
4. 在 **我的计划** 查看当前周处方和 4 周适应性路线；未来周不会被伪装为已确定处方。
5. 在 **我的资料** 查看当前 Pack 和数据边界；动作库可从当天训练或资料页进入。

完整说明见 [首次体验与本地运行](docs/zh-CN/quickstart.md)。

## 产品能力地图

| 阶段 | 用户能看到的能力 | 当前原则 |
| --- | --- | --- |
| 今天 | 今天该练什么 | 把当天的动作、时长和强度放在第一屏。 |
| 我的计划 | 当前周与适应性路线 | 只承诺当前周；未来周等待反馈后再生成。 |
| 评估 | 当前目标、近期运动与现实时间 | 匹配 Pack 后，用两步生成适合当前状态的训练起点。 |
| 进展 | 单次完成情况与 RPE | 自动汇总本周，让规则决定接下来的训练如何调整。 |
| 我的资料 | 当前 Pack、数据使用与边界 | 显示哪些信息用于当前路径，哪些仍为 Not tested。 |

机构交付、测试员操作与复测逻辑见 [产品说明](docs/zh-CN/product-guide.md)。

## 当前状态与验证计划

SportRX 当前的自动处方模块是**有氧运动处方原型**，不是已完成验证的医疗、预测
或赛事系统。平台只能在对应 Pack 具备规则、证据映射和测试时开启自动处方。当前
工作重点是验证第一条已发布的自用闭环能否被正确使用，并建立新增 Pack 的审阅与
发布质量门槛：

1. 自用：完成当前周训练、单次 RPE/完成记录与下一周调整。
2. 小样本试用：观察首次设置、第一节训练与周反馈能否独立完成。
3. 再评估某一新 Pack 是否具备独立的规则、证据映射、模拟测试和真实复测研究条件。

在积累足够真实数据与正式验证之前，SportRX 不会将内部规则、原型排序或测试
流程称为人群常模、运动准备度评分、风险预测或赛事能力预测。

## 安全与产品边界

SportRX 不提供疾病诊断、医疗清除、伤病风险百分比、完赛概率、假百分位、赛事
认证、营养建议或 AI 自动处方。出现需要进一步专业评估的信息时，系统会停止自动
生成或调整训练计划。AI 也不决定安全状态、训练强度、周运动量或进阶。

完整边界见 [产品边界](docs/zh-CN/claim-boundaries.md)。

## 项目结构

```text
SportRX/
├── app/          # Streamlit 本地演示
├── sportrx/      # 规则引擎、测量记录、报告与导出
├── data/program_packs/ # 版本化的人群处方包与发布边界
├── evidence/     # 证据库、结构化规则记录与内部审阅检索评测
├── data/exercises/# 本地动作内容库、来源与第三方许可说明
├── docs/zh-CN/   # 面向中文使用者的公开说明
├── examples/     # 示例输入与输出
└── tests/        # 本地验证测试
```

证据库、规则 ID、数据 schema 和原始文献链接继续使用英文，避免维护两套逐字
技术文件。中文页面提供产品层说明，并链接到对应的公开技术材料。

内部循证记录将来源、可支持结论、产品规则和测试协议连成可审阅链条。它只用于
规则审阅与未来的受限解释，不是用户聊天机器人，也不会改变训练剂量。测量组件的
证据状态与不可声称内容见
[Benchmark 组件证据台账](evidence/source_notes/006_benchmark_component_evidence.md)。

## 内部知识 RAG

SportRX 另有一个内部研究型 Knowledge Lab，用于检索已审核的运动科学知识卡并
在通过门槛后生成带引用和局限的中文研究摘要。它与 v0.1 的规则引擎分开：知识
RAG 不能改变安全边界、训练剂量或进阶，也不会作为公开用户聊天功能。它是未来
研究资产，不是当前默认产品体验。其公开元数据与审核规则见
[Knowledge Corpus](evidence/knowledge/README.md)。
