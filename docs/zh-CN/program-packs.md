# Program Pack 与平台路径

SportRX 的目标不是用一条万能规则服务所有人，而是用同一个处方内核承载一组可单独审核、测试、发布和撤回的 `Program Pack`。

## 用户如何进入方案

用户不需要先给自己贴人群标签。首次体验只回答：

```text
我想改善什么？
→ 我目前能做多少？
→ 我有多少时间和资源？
→ 是否有需要先确认的情况？
→ 今天从什么开始？
```

系统据此匹配当前场景对应的 Pack，并明确显示：当前适用路径、用于路由的信息、尚未测量的信息，以及为什么某些路径暂未开放。

```text
当前场景 + 目标 + 近期能力 + 时间 + 安全路由
                         ↓
                    Program Pack
                         ↓
                当前周规则化处方
                         ↓
            完成情况 + RPE + 可选测量记录
                         ↓
                 仅按该 Pack 的规则调整
```

| --- | --- | --- |

| 运动表现目标入门：测量优先路径 | 仅评估 | 进入测量与训练记录准备；不生成专项训练、赛事预测或排名。 |

高龄、孕产期、青少年、慢病、术后和康复情境会进入专业协作路线。SportRX 可以提供数据、协议和执行记录，但在独立 Pack、专业审核和验证完成前，不显示自动处方。

## Pack 必须包含什么

每个 Pack 都是版本化 JSON 配置，至少包含：

1. 适用与不适用条件。
2. 会影响路径或剂量的最小输入字段。
3. 规则 ID、起点边界、进阶/降低/暂停条件和撤回开关。
4. 可使用的测量协议与复测限制。
5. 动作、器械和场地的内容映射。
6. 证据版本、允许文案和局限。
7. 发布状态、QA 和测试要求。

动作库、证据库、可穿戴数据和 AI 都不能跳过 Pack 直接决定训练剂量。只有当前 Pack 引用的规则可以决定当前周处方或调整。

## 六库一图谱

| 资产 | 作用 | 是否直接决定剂量 |
| --- | --- | --- |
| 证据库 | 记录来源、结论、适用限制和证据等级 | 否 |
| 人群图谱 | 描述场景、目标、资源与路由条件 | 否 |
| 规则库 | 处方、进阶、降低和暂停规则 | 是 |
| 动作与场景库 | 提供动作、器械、替代方案与执行说明 | 否 |
| 测量库 | 记录测试协议、单位、来源、质量与复测条件 | 仅在 Pack 明确允许时 |
| 用户纵向库 | 保存计划、实际完成、RPE、测量和协议偏差 | 仅按规则库处理 |
| 知识图谱 | 连接人群、目标、测量、规则、动作和证据 | 否 |

## 统一记录边界

未来的设备、场馆或手动导入都只会写入结构化 `Measurement` 或 `CompletedSession` 记录。每条记录必须带来源、时间、单位、质量和用户授权状态；未做的测试保持 `Not tested`，不会用平均值或模型补齐。

设备数据不会直接改写今天的训练剂量。它只有在特定 Pack 完成评估、规则审核和发布后，才可能作为该 Pack 的一个输入。

## 当前不做的事

SportRX 当前不提供医疗清除、诊断、伤病风险百分比、完赛预测、假百分位、赛事排名、营养建议或 AI 自动处方。知识 RAG 仅用于内部研究检索与证据审阅，不能改变安全路由、规则或训练剂量。
