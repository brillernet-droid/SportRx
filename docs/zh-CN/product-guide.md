# 产品说明

SportRX 是一个从测量走向训练交接、再回到复测的决策原型。它的中心不是聊天窗口，
也不是一个综合分数，而是清楚区分：已经测到什么、仍然不知道什么，以及下一步
最有用的动作是什么。

## 核心模块

| 模块 | 作用 | 不能做什么 |
| --- | --- | --- |
| Safety Gate | 在进入自动训练交接前进行基础风险分流。 | 不诊断疾病，不提供医疗清除，不参与表现评分。 |
| Quick Match | 用近期训练行为和现实约束进行粗筛与路线说明。 | 不用自报替代实测，不收集配速成绩冒充 Benchmark。 |
| Hybrid Benchmark v1 | 通过标准路径和低器械路径记录可复测的原始表现。 | 不把不同协议强行换算，不生成假常模。 |
| Training Profile | 呈现当前测量画像、已测、`Not tested`、strongest area 与 what needs work。 | 不展示未经验证的 readiness score。 |
| Starter Path | 在满足安全和测量门槛时，提供保守的 4 周训练交接。 | 不替代教练、医疗人员或个体化诊疗。 |
| Retest | 结合完成情况、RPE 和同协议测试观察变化。 | 不将单次变化解释为确定的训练效果。 |

## 个人体验流程

```text
近期训练与约束
        ↓
Safety Gate + Quick Match
        ↓
Hybrid Benchmark（已测 / Not tested）
        ↓
Training Profile
        ↓
Starter Path 或下一项测量动作
        ↓
完成率 + RPE + Retest
```

Safety Gate 可以停止自动训练交接，但不会让一个人的表现画像变高或变低。表现比较
需要至少两个已测表现维度；测量不足时，产品应引导回 Benchmark，而不是勉强给出
看似个性化的训练计划。

## 机构交付流程

### 健身房

成员进入场馆后，先完成基础分流与 Benchmark，再获得 Training Profile。教练、
私教和团课可基于同一份记录沟通；复测让第一次评估变为持续服务，而不是卖课前
问卷。

### 跑团与训练营

跑团可在赛季开始、训练营分层或阶段节点安排 Benchmark。报告重点是当前已测能力、
缺失项目和下一步，而不是“能否完赛”的概率。

### 测试员

测试员应在测试前固定路径、器械、负荷和顺序；测试中记录原始数据、RPE 和偏差；
测试后解释已测、`Not tested` 与复测条件。测试员 SOP 和数据质量比页面数量更重要。

## 复测逻辑

SportRX 将完成率与 RPE 作为训练反馈，而不是把它们伪装成恢复评分：

- 完成率高且 RPE 合适：维持或小幅进阶；
- 完成率高但 RPE 明显偏低：可谨慎增加；
- 完成率低、RPE 偏高或出现异常：不进阶、降低负荷或暂停自动调整；
- 复测：优先使用同一协议与相近条件，再讨论原始变化。
