# SportRx Positioning After Open Source Scan

## Not This

SportRx should not become:

- an AI fitness coach,
- a generic workout tracker,
- a wearable dashboard,
- a HYROX social app,
- a medical risk calculator,
- or an all-in-one health app.

Those categories already exist and are crowded.

## This

SportRx should become:

> A measurement-first sport-science assessment and prescription prototype for
> recreational athletes.

## Positioning Sentence

SportRx helps recreational athletes understand what has actually been measured,
what is still unknown, and what conservative training focus makes sense next.

## Product Center

The center is not a chat screen or a plan generator.

The center is:

```text
Benchmark -> Training Profile -> Starter Path -> Retest
```

## Competitive Advantage To Build

1. Evidence-linked rules.
2. Raw benchmark records.
3. Conservative claims.
4. Retest-based progress.
5. User-owned data.
6. Metric source labels.
7. Rule-coded plan adjustment.
8. Protocol documents and review checks.

## Product Smell Test

When adding a feature, ask:

1. Does this improve measurement quality?
2. Does this improve explainability?
3. Does this help collect pilot validation data?
4. Does this preserve the safety/performance boundary?

If not, defer it.

## GitHub Scan Takeaway

The best adjacent open-source projects are strong because they are specific:

- data-format projects protect user-owned logs,
- endurance planners connect plan and actual execution,
- physiology-lab projects label the source and method behind each metric,
- protocol-driven projects make instructions and bad-response checks inspectable,
- HYROX tools capture station-level detail.

SportRx should combine those lessons around one narrower loop:

```text
measure -> profile -> prescribe -> execute -> retest
```

It should not become a broader app just because broader apps exist.
